色花堂检索页逻辑

色花堂.js v5.25 · 仅 /search.php 页面 · 原站一页 30 条结果

1

页面加载 · onDomReady()

路径含 /search.php 才进检索页分支。先无条件过一遍 injectQueueSwitch()，再调 searchBusyRetry()。

2

searchBusyRetry() · 拦截判断

判据是「页面上有没有 #threadlist li.pbw」，不是文案。可重试分支重试成功后只替换 #threadlist + .pg，不整页刷新。

有结果条目直接放行，进第 3 步
可重试限频 / 5xx / 超时：按原站给的秒数倒计时，fetch 重试
不可重试验证码 / 未登录：提示，停
空壳页无结果也无提示 → 快照失效，停
3

searchPageMain() · 初始化

清旧开关/分页条 → 读 URL 的 page 还原 readPages → collectSearchItems() 收集条目 → searchTotalPages() 取总页数 → 挂过滤开关和分页条。

4

applyFilter() · 过滤 + 切片

遍历 searchState.items，按勾选的栏目算出谁该显示 → 得到 matched 数组 → 按 page 切出第 (page-1)×30 到 page×30 条 → 其余的 display:none。

补齐循环 · 每轮间隔 5 秒，单轮上限 12 页
5

scheduleFill() · 决定要不要补

条件：matched < page × 30 且还有 nextUrl 且 fetched < 12 且没暂停。满足就 setTimeout(fillNextPage, 5000)。

6

fillNextPage() · 抓下一页

fetchSearchPage(nextUrl) → 成功则 appendSearchItems() 追加（按 tid 去重）→ readPages+1 → syncUrlPage() 写回 URL → 回到第 4 步重算。

抓成功追加 → 重算 → 继续下一轮
限频 / 超时停手，按钮留给用户手动重试
快照失效按钮变「重新搜索」
7

渲染 · loadDetailThumbs() + 胶囊

对当前可见的条目逐帖抓详情页取图（并发 5），图片按 4 张/秒进加载池；右下角胶囊实时统计成功/等待/失败/总数。

用户操作怎么改变状态

上一页 / 下一页

page ± 1 → applyFilter → pill.reset() 胶囊清零 → 给新一页取图 → 写回 URL。
本页没补满时「下一页」禁用。

继续补齐

清空 error / paused / fetched → 重新进补齐循环。胶囊继续累加，不清零。

勾选 / 取消栏目

回到第 1 页 → applyFilter 重算 → 存 localStorage → 给新可见的条目取图 → 重新补齐。

重新搜索（仅失效时出现）

用当前关键词重新发起一次搜索，拿新的 searchmd5，从第 1 页重来。

searchState 字段

字段作用
items所有抓到的条目 {el, forum, matches}，含补齐进来的
page脚本自己的页码（筛选结果分页），和原站页码不是一个维度
readPages已读到原站第几页，状态栏显示 + 写进 URL 用
totalPages原站总页数，从分页条最大 page=N 推
nextUrl原站「下一页」链接，抓不到就没有了
fetched本轮补抓了几页，只用于 12 页上限保护；点「继续补齐」清零
filling / paused / error运行态：正在抓 / 用户暂停 / 上一次失败原因
expired搜索快照失效，重试没意义
两个硬约束（来自原站，不是脚本能绕的）
  • 抓页间隔不能小于 5 秒 —— 实测 2 秒时抓 3 页就被限频。
  • 搜索结果是带时效的快照，searchmd5 过期后服务端返回既无结果也无提示的空壳页。实测读 8 页左右就可能失效，之后只能重搜。
