# Tampermonkey-enhance

针对图片/视频论坛的一小组 Tampermonkey 用户脚本。两件事：**把列表页缺的图补上**，以及**清掉广告与无用元素**。

加载策略统一为**打开即全量加载 + 滑动窗口限流**：`2048` 的列表页本来就有图地址，脚本摘掉原生 `loading=lazy` 交给窗口统一起跑；`色花堂`、`sis001` 的列表页本来没有图，先取到映射再建图。

脚本只在本机浏览器里改页面行为——不发请求抓取、不上传任何数据、不修改站点内容。

| `探花缩略图.js` | `sdy.685886.xyz` | 2.0 | 列表页居中显示详情页预览大图（单张）+ 列表/详情页去广告 |

## 安装

1. 浏览器安装 Tampermonkey；
2. 两种方式二选一：把 `.js` 文件**直接拖到 TM 面板**里；或 TM 面板 → 添加新脚本 → 清空编辑器 → 粘贴脚本全文 → `Ctrl+S`；
3. 打开对应站点，脚本自动生效（多为 `@run-at document-start`，`探花缩略图` 为 `document-idle`，刷新页面即可）。

改完脚本后注意：**TM 里存的副本与仓库里的文件是两份东西**，改完仓库文件要重新导入 TM 才会生效。

## 2048缩略图.js

### 原理

打开页面即全量预加载全部图片，滚动不再触发任何加载，用户自行滚动浏览。

- **滑动窗口**：需要加载的图全部登记进队列，同时在途的请求数不超过 `MAX_IMG_IN_FLIGHT`；每张结算（加载成功或放弃）后立刻补下一张。窗口位按次持有，重试的图重新排到队尾，慢图不会一直占着位子。
- **统一起跑**：站点给缩略图标的是原生 `loading=lazy`，而浏览器的视距阈值会越过任何窗口把整页请求一次性打出去（实测 47 张里有 40 张会被浏览器自己抓走）。所以脚本把窗口外的 `src` 摘下来、把 `loading` 改成 `eager`，轮到它时才写回地址发请求。
- **失败处理**：`error` 后按 `IMG_RETRY_BASE_MS` 的倍数退避重试（首两次用原地址，之后换查询串绕开已缓存的失败结果）；单张图受 `IMG_TOTAL_WAIT_MS` 约束；用尽后压暗标记，点击重新排队再试。
- **死图床熔断**：同一域名连续 `HOST_FAIL_THRESHOLD` 次**硬失败**（浏览器派发 `error`：DNS 失败 / 连接被拒 / HTTP 错误）后，该域名尚未开始的图直接判失败。**超时不算**——一次冷启动抖动不该把整个域名判死；任一成功即清零。
- **加载状态**：右下角常驻一个胶囊，样式与 `色花堂缩略图` 一致——加载中黑底 `缩略图加载中 12/47`，全部成功绿底 `缩略图 47 张已加载`，有失败橙底 `缩略图 44/47（3 张失败）`；结算后 `PROGRESS_HIDE_DELAY_MS` 淡出。
- **去广告**：`.recs-wrapper` / `.recs-head` / `.recs-row` / `.recs-pill` / `.nav-container` / `.movie-banner` 命中即整块移除；侧栏 `.r_two` 用 CSS 隐藏而不是删除，避免影响站点自身的布局计算。`.reward-card` 是站点的打赏功能卡，不删。
- **占位图**：站点给每个缩略图容器挂了 inline 的 `background-image: url(images/thumb-ing.gif)`（59KB，`background-size:cover` 会把它放大铺满整格）。脚本把它置空，这张图不再下载，未出图的格子露出父容器 `.display` 的 `#ced4da` 底色。
- **图床 preconnect**：`src` 被摘掉后 preload scanner 看不到图床地址，首次握手只能由脚本提前完成（实测单次 TCP+TLS ≈ 340ms）；按 origin 去重，不加 `crossorigin`（缩略图是普通 `<img>` 非 CORS 请求），https 页面里的 http 源不建。
- **`no-referrer` 只给跨域图**：同源图不受防盗链影响，不处理。
- **节点复用**：`src` 被站点改写时（详情页点 `.pimg` 会把地址写进 `.big_img[src]`）作废旧状态重新登记。脚本自己写的 `src` 用「写入值比对」跳过，不用读过即清的布尔标记——摘 src 与写回 src 会落进同一批 mutation 记录，布尔标记会被前一条消耗掉，后一条就被误判成换图。
- 只处理跨域图片（图床）；站内图标、相对路径装饰图一律不碰。空 `src` 不标记为已处理，站点稍后写进去（详情页的 `.big_img`）时再登记。
- `@grant none`：直接跑在页面上下文，无 GM API、无日志输出。

### 可调参数（文件顶部）

| 参数 | 默认 | 说明 |
|---|---|---|
| `MAX_IMG_IN_FLIGHT` | 8 | 同时在途的请求数上限；调大更快，但更容易触发图床限流 |
| `IMG_RETRY_TIMES` / `IMG_RETRY_BASE_MS` | 2 / 800ms | 单图失败重试次数与退避基数（另加 0~400ms 抖动） |
| `IMG_TOTAL_WAIT_MS` | 20000 | 单张图的总等待上限，跨所有重试共享；超时按失败结算并释放窗口位 |
| `HOST_FAIL_THRESHOLD` | 3 | 同一图床连续硬失败这么多次即判不可达；超时不算，任一成功即清零 |
| `PROGRESS_HIDE_DELAY_MS` | 2500ms | 全部结算后延迟这么久开始淡出（淡出 0.3s，再 0.4s 后移除） |
| `REMOVE_SELECTORS` | 站内广告类名 | 命中即整块移除 |
| `PRECONNECT_RETRY` | 25 | 预连接插入失败后的重试次数（4ms × 25 ≈ 100ms） |

### 这个站点的约束（改代码前先看）

- 列表页缩略图是「真实地址已写在 `src` + 原生 `loading=lazy`」，全站**没有** `data-src` / `data-srcset` / `data-original` 这类懒加载属性，站点自己的 10 个外部 JS 也不产生它们。
- 站点**没有自己的懒加载 JS，也没有 Ajax 分页**：翻页是普通 `<div class="pages">` 链接整页跳转，所以脚本不需要处理「追加行」，也没有滚动监听。
- 占位图是缩略图容器 `div.img` 的 **CSS 背景**，不在 `img` 的 `src` 里。
- **图床没有缩略图变体，也无法缩放**：`?w=` / `?width=` / `?imageView2` / `?x-oss-process` / `?thumb=` 等参数全部被忽略（返回一模一样的字节），`_thumb` / `thumb/` 路径变体与 `/cdn-cgi/image/` 都是 404。服务端侧压缩这条路走不通，体积只能靠「少加载」控制——这也是本脚本改为全量加载后仍要用滑动窗口限流的原因。
- **WebP 协商已经自动生效**：浏览器对 `<img>` 发出的 `Accept` 里带 `image/webp`，图床会回 `Content-Type: image/webp`，脚本不需要也无法再干预。
- **缓存已经是 30 天**（`Cache-Control: max-age=2592000`），所以重试优先用原地址、只在第 3 次才换查询串，避免把缓存键打散。
- 图床对单客户端限速、吞吐波动很大：实测有效吞吐 **90–180 KB/s**，而本机出口到公共 CDN 有 **800–1500 KB/s**；同一批冷请求两次跑的总耗时最多差 1.6 倍。
- 页面里有 **1 张 `data:` 内联图**；脚本只接管跨域 http(s) 图，内联图与相对路径装饰图直接放行（`new URL('data:...')` 的 origin 是字符串 `"null"`，不挡掉会打出一条无效的 preconnect）。
- 缩略图整体位于帖子链接 `<a href="read.php?tid=...">` 内部；卡片下方的标题链接是另一个进入帖子的入口。
- 详情页的 `<img class="big_img" src="">` 是一个空的放大图容器，点小图（`.pimg`）时由站点自身 JS 把地址写进它的 `src`。
- 图床**域名不固定**，单页常见 2~5 个。
- 该站搜索有 **180 秒/次冷却**（普通会员），且访问 `search.php?sch_time=newatc` 也计一次搜索。
- 与本系列另一个站点共用同一类 WAF（`safeid` 挑战页）。挑战页上脚本空转无害，等挑战通过即可。

### 实测（v4.0）

在官方镜像站上用真实 DOM + 真实图床注入运行：

- **滑动窗口生效**：列表页 47 张缩略图的峰值在途为 **8**（等于 `MAX_IMG_IN_FLIGHT`），未开始的图 `src` 为空、浏览器不会去抓；完成数随时间递增并在结算后补位，最终 47/47、0 失败。
- **窗口值怎么定的**：强制冷重下全部 47 张、按不同 `MAX_IMG_IN_FLIGHT` 实测——总耗时 4→16.7s、8→13.7s、16→17.4s、24→17.1s；8 与 16 各复现两轮得 8→11.0/11.7s、16→9.4/7.3s。**图床自身的吞吐波动远大于档位差异**，4–16 之间没有可复现的最优值，所以取保守的 8；24 只测到更慢。
- **无重复下载**：摘掉 `src` 再写回不会造成二次请求——实测 47 张缩略图在资源计时里各只有 1 条记录。
- **加载状态**：`缩略图加载中 8/47` → `缩略图 47 张已加载`，2.5 秒后淡出；详情页 9 张图同样正确结算后消失。
- **滚动不再触发任何加载**：脚本里已没有任何滚动监听或 `IntersectionObserver`。
- **去广告**：列表页 `recs-*` 全清；详情页 `nav-container`（20 条赌场外链）与 `movie-banner` 全清，`.reward-card`（打赏功能卡）保留，`.r_two` 为 `display:none`。
- **referrerPolicy 分布**：47 张跨域缩略图全部 `no-referrer`，同源图保持默认。
- **节点复用**：点 `.pimg` 后 `.big_img` 从空 `src` 被正确登记并加载。
- **失败链**：把某张图指向不存在的地址，自动重试 2 次后压暗；点击该图重新排队（`defaultPrevented=true`，页面不跳转）。
- 控制台无脚本报错（只有站点自身的 `core.js` / `post.js` / `Compatibility.js` 报错与 `chrome-extension://invalid/`）。

## 色花堂缩略图.js

### 原理

PC 列表页本身**没有缩略图**，脚本改成"从移动版模板取图，注入 PC 页"：

- 用 `GM_xmlhttpRequest` 带 **Android 移动 UA** 请求 `forum-{fid}-{page}.html?mobile=2`，服务端按 UA 返回触屏模板，解析 `.n5_htmk` 卡片得到 `tid → 该帖缩略图` 映射；
- **打开即全量加载**：映射到手就把整页缩略图全部建好并立刻发起请求，`loading=eager`，不设 `loading=lazy`、不监听滚动、不做任何按需加载；用户自己滚着看；
- 同时把行单列化（只留标题、发帖日期、缩略图；作者/回复数等列是**刻意删掉**的）、把发帖日期搬进标题下方、清掉表格内的公告行与广告行；
- 右下角常驻**加载进度**（`缩略图加载中 12/60` → `缩略图 60 张已加载` / `缩略图 57/60（3 张失败）`），全部结算后延迟 2.5 秒自动消失；
- **滑动发送窗口**：同时在途的图片请求不超过 `MAX_IMG_IN_FLIGHT`，每张结算后立刻补下一张——避免把 60 个请求一次性压给同一个图床而排成长队。窗口位是**按次**持有的，重试会重新排队到队尾，慢图不会一直占着位子；
- **失败自动重试**：单图失败按 `IMG_RETRY_BASE_MS` 的倍数退避重试（换查询串绕开已缓存的失败结果）；整张图的等待时间受 `IMG_TOTAL_WAIT_MS` 约束，重试用尽或预算耗尽才移除该图；
- **死域名熔断**：同一图床连续发生 `HOST_FAIL_THRESHOLD` 次**硬失败**（浏览器派发 `error`，即 DNS 失败 / 连接被拒 / HTTP 错误）后，该域名尚未开始的图片直接判失败。**超时不算**——否则一次冷启动抖动就会把整个域名误判成不可达；
- 搜索页：按栏目过滤结果 + 只对**可见**结果取详情图（并发 5），筛选变化时自动补跑；
- 详情页：宽屏 + 去广告；搜索繁忙自动刷新（有次数上限）。

### 可调参数（文件顶部）

| 参数 | 默认 | 说明 |
|---|---|---|
| `MOBILE_UA` | Android Chrome | 服务端分发触屏模板的**唯一开关**，别乱改 |
| `MAX_IMG_IN_FLIGHT` | 16 | 同时在途的缩略图请求数上限；**设 0 = 不限制** |
| `IMG_RETRY_TIMES` / `_BASE_MS` | 2 / 800ms | 单图失败重试次数与退避基数（另加 0~400ms 抖动） |
| `IMG_TOTAL_WAIT_MS` | 30000 | **单张图**的总等待上限，跨所有重试共享。快失败照样重试；图床无响应时最多耗掉这一个预算就放弃。不能调太小：经代理时一次冷连接实测就要 10 秒以上 |
| `HOST_FAIL_THRESHOLD` | 3 | 同一图床**硬失败**（浏览器派发 `error`：DNS 失败 / 连接被拒 / HTTP 错误）连续这么多次即判不可达，该域名尚未开始的图片直接判失败；**超时不算**，任一成功即清零 |
| `BELOW_FOLD_PRIORITY` | `'auto'` | 非首屏图的优先级；想让缩略图压过页面其余资源可改 `'high'` |
| `FOLD_SLACK_PX` | 120 | 首屏判定余量（行顶距视口底部在此范围内 → 首图标 `high`） |
| `MAX_THUMBS_PER_POST` | 5 | 每帖最多几张缩略图（触屏模板给 2 张，5 只是封顶）。版式按实际张数计算，**改这个值不需要同步改样式** |
| `THUMB_GAP_PX` | 8 | 缩略图间距，必须与 `--img-width` 的计算一致 |
| `PROGRESS_HIDE_DELAY` | 2500ms | 全部加载完成后进度提示延迟多久消失 |
| `MAX_CONCURRENT` | 5 | 详情页取图并发 |
| `MAX_DETAIL_IMGS` / `MAX_BUSY_RETRY` | 5 / 5 | 详情页单帖取图上限 / 搜索繁忙重试上限 |
| `MOBILE_RETRY_TIMES` / `_DELAY` | 2 / 1500ms | 移动版映射请求重试 |
| `DETAIL_RETRY_TIMES` / `_BASE_MS` | 3 / 2000ms | 详情页被反爬拦截后的退避重试（2s / 4s / 6s） |
| `PAGE_CACHE_TTL` / `_MAX` | 5 分钟 / 10 条 | 移动版映射的会话级缓存 |
| `DEBUG` | false | 日志开关 |

### 这个站点的约束（改代码前先看）

1. **必须用 GM 请求 + 移动 UA**。浏览器端伪装 UA 打开会被触屏模板自带的 `common.js` 用 `"ontouchend" in document` 判定后踢回 `forum.php?mobile=1`；GM 请求不执行 JS，所以只有 XHR 路径能稳定拿到触屏模板。仅带 `?mobile=2`、不换 UA 时服务端返回的不是触屏模板。
2. **反爬依赖会话 Cookie `_safe`**。显式写的 `Cookie: mobile=2` 会被 TM「合并」到浏览器 Cookie 之后，不要改成覆盖写法。首访/浏览器重启后 `_safe` 尚未建立，`document-start` 的抢跑请求必然拿到门页并被判为"被 safe 挑战页挡下"——属预期，DOM 就绪后的带重试流程会补上。
3. **图床强制校验 Referer**：缩略图 `<img>` **绝不能**加 `referrerPolicy="no-referrer"`（会 403）。
4. **图床没有缩略图变体**：`?w=` / `?width=` / `?imageView2` / `?x-oss-process` 全部忽略，`/cdn-cgi/image/` 返回 404，服务端侧无法压缩或缩放。Cloudflare Polish 已自动转码（`Vary: accept`，浏览器会协商到 WebP），脚本不需要也无法再干预。图片 `Cache-Control: max-age=2592000`（30 天）。因此全量加载的体积只能靠"每帖少取几张"来控制。
5. **图床域名不固定，且存在已经死掉的域名**。列表页实测单域名（`tu.djhdhs.us`），搜索结果页的图来自各帖详情页，除该域名外还会出现 `imgpile.com`、`qpic.ws` 等；实测 `qpic.ws` 已完全连不通（`ERR_CONNECTION_TIMED_OUT`），会白耗一轮重试。脚本对详情页取到的地址同样做预连接与域名学习（`preconnectUrlList`），并对连续失败的域名熔断（`HOST_FAIL_THRESHOLD`）。
6. **置顶帖在移动版是纯文字列表**，其卡片没有 `a[href*=viewthread]`，会被解析逻辑跳过 → PC 列表的置顶行不注入缩略图，与移动版展示一致。
7. **分页按钮会被还原成普通链接**。站点用 `static/js/autoloadpage.js` 接管 `#autopbn` 的点击、用 Ajax 往表格里追加下一页的 tbody；而该文件里 `autopagenum` 恒为 0，滚动到底本来也不会自动追加。被 Ajax 追加的行拿不到移动版映射，只会得到一整页无缩略图的行，所以脚本把 `#autopbn` 的 `onclick` 摘掉、`href` 还原成下一页地址：点击即整页跳转，走与首页一致的流程。这套机制只存在于论坛列表页；搜索结果页用的是普通 `.pg` 链接、没有 `#autopbn`，所以搜索页不调用它。
8. **18+ 年龄门**：`_safe` 尚未建立时服务端先返回年龄门，URL 仍是 `forum-103-1.html`。此时脚本直接退出（既没有行可注入，移动版请求也必然被挡下）。
9. 站点域名会轮换，脚本内 URL 一律用 `location.hostname` 拼。

### 实测（v3.0）

在官方镜像 `ynhe.h7rr6.com` 上用真实 DOM + 真实图床跑过完整流程：

**详情页取图被限流时的行为**：连续批量取详情图会触发站点的 safeid 挑战，脚本会按 `DETAIL_RETRY_TIMES` 退避重试 3 次，仍失败则记为 null —— 该帖**不标记已处理**（下次筛选变化或重进页面会重试），控制台输出 `详情页请求被反爬拦截: <tid>`。实测一次批量中 13 个 tid 被拦，所有"加载中…"占位都被正确清除、无残留、无脚本报错。

**版本核对**：脚本会把 `@version` 写到 `<html data-sehua="3.0">`。在控制台执行
`document.documentElement.dataset.sehua` 即可确认浏览器里实际跑的是哪一版——改了文件但没重新导入时一眼可见。

## 探花缩略图.js

### 原理

站点 2026-10 改版，**列表页与详情页都变成了 JS 渲染**：服务端只回一个壳 + `window.__data__` 内联 JSON，内容由 `/js/*.js` 在浏览器端生成。所以"抓静态 HTML 解析 DOM"的老办法全部失效（老版脚本的 `.img_item` 选择器与 base64 解码逻辑已死）。

- **列表页**：`document-idle` 后站点 JS 才渲染，所以轮询等 `UL.list` 出现再逐条处理；分页是整页刷新，不用 history 钩子。
- **详情页**：用 `GM_xmlhttpRequest` 取壳（约 3.5KB）——它**不执行页面 JS**，拿不到 DOM——直接正则从内联 JSON 里取 `domain_image` / `picture_dir` / `resolution`。
- **预览图**：`https://{domain_image}/capture/{picture_dir}/t4.jpg`，只取这一张（站点桌面分支）。
- **居中显示**：外层 `text-align: center` + `img{margin:0 auto}`；横版按原始尺寸撑满，竖版封顶 `portraitMaxHeight`。
- **去广告**：列表页与详情页都删 `#hf-container` / `#dp-container` / `#icon-wrapper`，外加页脚的 SEO 链接农场。**绝不删 `#content`**——它就是列表/正文容器，删了等于删内容。详情页内容是异步渲染的，所以挂 `MutationObserver`（只监听 `childList`）持续清，**不设停机时间**：观察器随页面销毁自动回收，翻上/下一篇本来就是整页刷新，这样连"渲染完才注入的广告"也能清掉（已用延迟注入的广告实测验证）。
- **详情页只去广告、不动布局**：列表页那套 `.row{max-width:100%}` 加宽**不在详情页执行**，实测详情页 `#page/#content/article` 宽度与站点原状一致（1172/1000/1000）。
- **承重样式别乱删**：站点原生 `.row` 是 `max-width:1000px`、`.videos-list` 是 `overflow:hidden`，这两条覆盖去掉后预览图会被压回 1000px 并被裁掉。

### ⚠️ 这个站最容易踩的两个坑

1. **`#content` 就是列表/正文容器，绝对不能删。** 一删整页内容消失（正文或列表）。真正的广告位只有 `#hf-container` / `#dp-container` / `#icon-wrapper`。
2. **类名避开 `.preview-loading` / `.capture-col`**：站点自己的预览组件在用，撞名会互相干扰。本脚本统一 `tht-` 前缀。

### 可调参数（文件顶部）

| 参数 | 默认 | 说明 |
|---|---|---|
| `imageName` | `t4.jpg` | 只取站点桌面分支那一张；想换/加图改这里 |
| `portraitMaxHeight` | 640 | **竖版**图高度上限（px）；横版不受限，**设 0 = 竖版也不限** |
| `showResolutionBadge` | true | 标题后显示 `1280x720` 徽章 |
| `adSelectors` | `#hf-container` / `#dp-container` / `#icon-wrapper` | 列表页与详情页都要删的广告块；想留哪个从这里删一行 |
| `removeFooterFarm` | true | 删页脚的 SEO 链接农场（25 条站外垃圾外链）；**false = 保留页脚** |
| `maxConcurrent` / `requestTimeout` | 6 / 15000ms | 详情页并发与超时 |
| `listPollInterval` / `listMaxWait` | 300ms / 15000ms | 等站点渲染出列表的轮询间隔与总时长 |

### 这个站点的约束（改代码前先看）

1. **详情页 `<picture>` 里有两条分支**：`<source media="(max-width:767.98px)" srcset="...t2.jpg">`（移动）+ `<img src="...t4.jpg">`（桌面）。站点同时只显示一条，所以"详情页只有一张图"——但同目录下确实还存在 `t2.jpg` / `cover.jpg`（且 `cover.jpg` 并非每部都有）。本脚本只用桌面的 `t4.jpg`。
2. **`t4.jpg` 横竖都有**（横 1200x694 居多；竖见 1200x2086 / 1000x1742 等），必须按 `naturalWidth/naturalHeight` 判方向，否则竖版满宽会撑到近 2000px 高。
3. **列表项结构**：`UL.list > LI > span.list_item > a[href*="movie.php"]`；标题里塞了大量隐藏 `<span>` 反爬字符（取标题文本时要小心）。
4. **`@match` 只写了两个域名**，站点"永久回家地址"在轮换（`thbt5/7/8/9.com` 等），换域名后需自己补一条。
5. **详情页正文里这些是真内容，不能当广告删**：`#primary > main > article > .entry-content` 下的 `.video-infos`（标题）、`.video-description`（发布时间 / 格式 / 大小 / 时长 / 分辨率 / Hash）、`.preview-grid > .capture-col`（站点自己的预览图）、`P#magnet-link` 与下载/复制磁力按钮、`.pagination-nav`（上一篇/下一篇）。**真正的广告只有 `#hf-container` / `#dp-container` / `#icon-wrapper`**（`#icon-wrapper > .partner-zone` 是正文里那面"合作伙伴"广告图墙）。
6. **两个页面顶层结构相同**：`#page > .header.row / .clear / .row / #content`，而 `#content` 下是 `#hf-container` → `#primary` → `#dp-container` → `#colophon`。所以同一套 `removeAds()` 列表页和详情页都能用（这也是 `#content` 绝对不能删的另一重原因：它在两个页面里都装着正文/列表）。

### 实测（v2.3）

**列表页**（`tdc.259298.com/list.php?classid=1`）

- 每项 `1 张预览 + 1 个徽章`，`失败 0`；全部 `src` 都是 `t4.jpg`；横竖都有，全部居中（左右留白恒等）。
- 预览图铺满整行：实测 `li 1137 - padding 20 = 1117`，`.tht-preview` 盒宽就是 1117。
- 横版按原始尺寸渲染（1200x694，容器不够宽时等比例缩到 `max-width`）；竖版封顶 640px 且居中（1200x2086 → 368x640）。
- 只对**竖版**限高：给所有图设 `max-height` 会多余地缩小横版（1200x2086 → 368x640，横版按原始尺寸）。

**详情页**（`/movie.php?...`）

- 4 处广告位（`#hf-container` / `#dp-container` / `#icon-wrapper` / 页脚 25 条站外外链）全部清除。
- 正文 H1 / 8 条元数据 / `.capture-col` 预览图 / 磁力链 / 上下一篇 **全部保留**。
- **延迟注入的广告也会被清掉**：脚本跑完后手工往 `#content` 塞 `#dp-container` 与 `#icon-wrapper`，300ms 内即被观察器移除。
- 布局零改动：`#page 1172 / #content 1000 / article 1000` 与站点原状一致（详情页不跑加宽样式，也不注入任何 `<style>`）。
- 无悬浮（`position: fixed`）广告；页脚之外没有其他站外链接聚集块。

### 承重项与保险项（改代码前先看）

| 项 | 理由 |
|---|---|
| `.row { max-width:100% }` | 站点原生 1000px；去掉后预览图被压回 1000px |
| `.videos-list { overflow:visible }` | 站点原生 `hidden`；去掉后放大的图被裁 |
| `#site-navigation ul { max-width:100% }` | 站点原生 1350px；内容加宽后导航跟着加宽才对齐 |
| `.tht-preview > a { line-height:0 }` | 一行防御，防止将来 img 变回 inline 时出基线缝隙 |
| `findListItems` 的 `'.videos-list ul li'` | 锚点与 `ul.list` 不同，是 ul 类名被换时的保险 |
| `@connect *` | 不锁死域名，避免补 `@match` 时还要同步补 `@connect` |

## 两个脚本共通的注意事项

- **加载策略**：`2048缩略图` v4.0 起与 `色花堂` v3.0 起都是打开即全量加载，靠滑动窗口（`MAX_IMG_IN_FLIGHT`）限制在途请求数；两个脚本没有共用参数。
- **`@match` 只写了单个域名**，站点换域名后脚本会**静默失效**（这些站点换域名很频繁）。脚本内部已经用 `location.hostname` 动态拼 URL，补一条 `@match` 即可复用（色花堂还要补 `@connect`）。
- 两个站点共用同一类 `safeid` WAF：挑战页上脚本空转、无害；色花堂那份有 `isSafePage()` 检测，2048 那份 `@grant none` 无从绕过。
- 排查脚本行为时优先看 `色花堂` 的 `DEBUG = true` 日志；2048 那份不打日志，只能靠 DOM 状态（`_picked` / `_state` / `_tries` / `_url` 等标记）与右下角进度条判断。
- **改完仓库文件必须重新导入 TM 才生效**，两者是两份副本。用 `<html data-sehua>` 可即时确认跑的是哪一版。
