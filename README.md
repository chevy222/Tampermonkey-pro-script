# Tampermonkey-enhance

一组给图片论坛用的油猴脚本。核心作用：**打开页面就把图全部加载好，不用一边滚一边等**，顺带清掉广告和无用元素。

适合不看代码、只想装完就用的人。

---

## 一、四个脚本分别是什么

| 脚本 | 用在哪个站 | 装完会怎样 |
|---|---|---|
| `2048缩略图.js` | `bbs.hdaksog.com` | 图片打开页面立刻开始下载，不用滚动；右下角有加载进度；广告推荐块和右侧边栏消失 |
| `色花堂缩略图.js` | `bhagq.4yl7j.com` | 列表页每帖下面自动出现缩略图；页面变宽屏单列；搜索页能勾选屏蔽不想看的栏目；帖子正文图开页即全部加载 |
| `探花缩略图.js` | `sdy.685886.xyz` | 列表页每行居中显示一张预览大图；广告消失 |
| `sis001缩略图.js` | `www.sis001.com/forum/` 列表页 | 每个帖子后面显示缩略图 |

---

## 二、安装

1. 浏览器装扩展 [Tampermonkey](https://www.tampermonkey.net/)（油猴）；
2. 打开油猴面板 → **添加新脚本**；
3. 把对应 `.js` 文件的全部内容粘贴进去，按 `Ctrl + S` 保存；
4. 打开对应站点，刷新页面。

**怎么确认生效了？**

- **2048 / 色花堂**：右下角出现一个黑色小胶囊，写着 `缩略图已完成 12/47` 之类的字样。
- **探花 / sis001**：列表里直接出现了图片。

> 改了 `.js` 文件之后，必须回油猴面板里重新粘贴保存才会生效。如果没提示更新，就删掉旧脚本重新添加。

## 三、常见问题

### 完全没反应

1. 油猴扩展是不是开着、脚本前面的开关是不是绿色；
2. 站点域名是不是变了 —— 脚本只对特定域名生效，域名换了要改脚本开头的 `@match` 那一行；
3. 刷新一次页面；
4. 还不行就删掉脚本重新导入。

### 图加载不出来，进度条长时间不动

**这几乎都是图床（存图片的服务器）那边的问题，不是脚本坏了。**

- 进度停在 `6/90` 很长时间 = 那批图片的服务器接了请求但不回数据。脚本会等到超时（45 秒）才标失败；只要图已经能看见就不会算失败。
- 进度最后显示 `40/47（7 张失败）`（橙色）= 这 7 张确实下不下来，换时间再试通常就好。
- 想立刻重试失败的图：**点一下变暗的图，或者点它右上角的 ↻**。
- 整页都慢 = 那个图床本身在限速。脚本会自动跳过反复失败的图床，不会一直卡着。

### 控制台有红色报错

按 `F12` 看到的红色报错，绝大多数是网站自己的代码在报错，不是脚本的。脚本自己的日志都带前缀 `[2048缩略图]` 或 `[色花堂缩略图]`，没有这个前缀就不是脚本的。

### 想让脚本重试之前失败的图

脚本会把失败的图记在浏览器里，5 分钟内不再重试。想立刻清掉：

1. 按 `F12` → **Application** → **Local Storage** → 点开当前站点；
2. 删掉 `t2048BadImages`（2048 站）或 `sehuaBadImages`（色花堂站）；
3. 刷新页面。

### 色花堂列表页太费流量

移动版拿到的图片地址就是原图（单张 1~4 MB）。脚本拿到几张就显示几张。如果嫌费流量，可以在色花堂脚本里找到 `createThumbWrap` 函数，给 `urls` 加个 `.slice(0, 1)`，每帖只留 1 张。

## 四、想改设置

脚本的开关都在**文件最上面那一段**。在油猴面板里点「编辑」，改完 `Ctrl + S` 保存，刷新页面生效。

| 我的目的 | 改哪里 |
|---|---|
| 图床特别慢，想多等一会儿 | `IMG_TOTAL_WAIT_MS` 调大（毫秒，`60000` = 60 秒） |
| 不想让色花堂提前加载下一页 | 色花堂脚本里把 `PREFETCH_NEXT_PAGE` 改成 `false` |
| 搜索页想隐藏别的栏目 | 色花堂脚本里改 `BLOCK_FORUMS` 里的栏目名 |
| 还有广告没清掉 | 把广告元素的样式名加进 `REMOVE_SELECTORS`（2048 脚本） |
| 想看运行日志 | 把 `DEBUG` 改成 `true`，在 `F12` 控制台看 |

其他参数（同时下载数、重试次数、图床熔断阈值等）一般不需要动。

---

## 五、隐私

脚本**只在你自己浏览器里改页面显示**，不收集、不上传任何数据。唯一例外是色花堂脚本为了拿缩略图，会用你已登录的身份去请求该站自己的移动版页面 —— 请求对象仍然是这个站点本身。
